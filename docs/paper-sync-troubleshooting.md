# 论文知识库 · 故障排查

| 现象 | 原因与处理 |
|---|---|
| `另一个同步进程可能正在运行（锁 ...）` | 有同步进程未退出或异常残留。确认无进程后删除 `<数据目录>/.lock`；锁超过 6 小时会被自动清理 |
| `digest/config.json 缺少 api_key` | 复用的 DeepSeek 配置缺失，补齐后重跑；或用 `--offline` 跳过 AI |
| `会话 xxx 待人工确认归属` | 导出数据无法证明该对话属于「论文阅读」项目。把对话 ID 加入 `<数据目录>/conversation_ids.txt` 或配置 `config.json` 的 `project_ids` 后重新 `sync` |
| `无法识别论文（无 DOI/arXiv/标题）` | 对话里没有可提取的标识符。手工建 `manual_map.json` 映射，或在对话/笔记里补 DOI |
| `敏感素材拦截：...` | 素材中存在疑似密钥且脱敏后仍残留。清理素材后重跑；确属误报可临时调整 `digest/security.py` 的模式（谨慎） |
| `发布被拦截。清理内容后重试` | 成稿含敏感信息（路径/密钥/邮箱等）。编辑私有草稿后重新 `publish`；确认无风险用 `--force` |
| `归纳失败（已重试）` | DeepSeek 网络抖动或输出不合 schema。重跑 `sync` 即可（失败来源会自动重试）；持续失败换模型或用 `--offline` |
| 同步卡死/中断后恢复 | 直接重跑 `sync`：状态库按哈希跳过已完成部分，失败部分自动重试 |
| 论文已发布但源文件被删 | 正常：已发布内容不受 inbox 变化影响 |
| 构建后 /papers/ 404 | 检查 `src/content/papers/` 是否有文件、frontmatter 是否合法（构建日志会指出具体文件） |
| 需要回滚某篇论文 | 从 `src/content/papers/` 删除对应 md 并 push；私有草稿仍在数据目录中保留 |
