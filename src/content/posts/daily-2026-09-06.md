## P7-D0a：三次打回换来的两条教训

今天最主要的时间花在 D0a 上。我新写了一个 (g,t) 身份事件级分类器，把 Q1 的低 R_m 延续失败拆到 detector / candidate-access / lifecycle / assignment 几个族上。

第一版跑出来很“漂亮”：detector 37.85%，F4 = 0，归因看起来完全，门判定 CONTINUE。但复审直接打回，问题是**门通过是构造出来的**——分类函数所有分支都不返回 F4，所以“F4 = 0、unresolved 门通过”根本不是数据证据，summary 里现在明确标注为空洞满足。同一轮还发现 horizon 判定有一帧偏差（应为 gap−1 ≤ max_time_lost），以及 R_m 回填口径需要降级为 secondary。

第二轮修完，数字翻了个面：candidate-access 升到 47.6%，超过 detector 成为最大族。复审又抓到一个更本质的问题——既然接受了“身份正确的延续不算失败”，那它就必须**压过一切审计分支，包括规范 true detection 完全缺席的情形**。原先 F0 排在 F3 之后，导致 34 个（Q1 10 个）“规范 D* 缺席但实际延续了同身份”的事件被双重记账。分类序最终定稿为 `F0(身份) → F3 → F2c → F2a → F2b → F1a/F1b → F4`，重跑后与复审给的 34/10 精确对账，每个都能凭交付产物里的四列证据复核。

最终 180/180 测试通过，两遍全量运行的四份产物逐字节一致。结论是 candidate-access 52.84%、detector 39.26%，detector 在 0/7 序列中成为最大族——early-STOP 不成立，但 FR-4 的预警显著加强：如果 F2a 主导在 D0b 复现，proximity-gate M2B 大概率不成立，得另立 stage-routing amendment。

## E0：跨域权重能跑，但只算“被检验的假设”

E0 的第一道坎是权重。计划默认的 mot17_sbs_S50 并不在本地，而官方渠道全部落空：fastReID 的 release 里没有 mot17 专用权重，BoT-SORT 把它挂在网盘，镜像站也搜不到。最后手动放好权重，校验 317 MB 文件的 SHA256 后冻结了 `reid_manifest.json`。

FastReID 是 2021 年的代码，配现在这套 torch 需要打两处最小兼容补丁，这些都记进了 manifest。加载冒烟测试通过，输出 2048 维 L2 归一化特征。随后生成 per-detection 外观缓存，415,573 个嵌入，两遍产出 8 份文件逐字节一致。

A0-R 与 A0 的对比印证了预期方向：关联指标小幅改善（AssA +0.75、IDF1 +0.72、IDSW −6），检测指标轻微下降（MOTA −0.33）。外观通道真实存在，但幅度温和——这和 D0a 里 assignment 只占 4.4% 是一致的，创新点不在关联打分的精调上。S0 的结果更让人放心：pooled ρ 0.4773 对 P6 的 0.4818 几乎无损，说明冻结打分器几乎不损失信息。

## 顺带验证了一个想法：每日对话自动成稿

我想让博客每天自动检索我在 Codex 和 ZCode 里的对话，归纳后发布。调研结论是可做：Codex 的会话按日期存成 JSONL，ZCode 存在本地 SQLite 里，两边都能全自动读取；ZCode 侧可以按真实用户来源精确排除系统注入的上下文，Codex 侧要区分注入内容。方案已经成型，但还没动手实现。
