## 今日重点

- **我在新的 AutoDL 实例上搭好了 PlugTrack（DiffMOT）可复现工作的基础**：conda 环境、两个官方仓库锁定到指定 commit、DiffMOT 官方权重与 detections 全部到位，完整导入链（torchreid、fastreid、lap、cython_bbox、官方 D2MP）一次通过。
- **检查官方代码时发现一条关键事实：官方 `main.py` 里 `init_seeds` 虽然定义了，但从未被调用，`seed:123` 在 eval 路径上实际没有生效。** 因此，官方复现按原样不额外加 seed，这条会写进偏差记录。
- **目前唯一无法推进的问题：PlugTrack 官方“Pretrained Models”的 6 个 Google Drive 子文件夹全部为空**，包括我们需要的 `plugtrack_diffmot_dance`；GitHub issues 里也没有备用链接。

## 给复现定规矩

今天真正的工作是**可审计地**复现，而不仅仅是把代码跑起来。所有设置分四类标注：PAPER-SPECIFIED / OFFICIAL-REPO-SPECIFIED / COMPATIBILITY-CHOICE / OUR-METHOD，任何与官方不一致的地方都写入 manifests，而不是只留在脑子里。硬件跟论文对得上：4090 24G，驱动 580.76.05，gcc 9.4 足以编译 lap 和 cython-bbox。这省了不少事。

## 环境与代码锁定

环境 `plugtrack-repro`（Python 3.9.25）加 torch 2.0.1+cu118，CUDA 验证通过。两个仓库 clone 后锁到指定 commit，并生成 commit 清单。官方配置读下来与论文完全吻合：HMINet、interval=5、encoder_dim=256、tf_layer=3、epochs=800、batch=2048、high 0.6 / low 0.4、w_assoc_emb 2.2、aw_param 1.7。只有 `gpus` 列表和各类路径是作者机器的，按我们的硬件改，记为 COMPATIBILITY-CHOICE。

另外有三个发现会影响后续所有操作：

1. DiffMOT 官方仓库自带 TrackEval，评估器直接用它，不必另找一套。
2. `external/__init__.py` 用 `getcwd()/external` 拼 sys.path，意味着**所有 eval 必须在 DiffMOT 根目录下启动**，已写进运行协议。
3. eval 模式下的 `DiffMOTDataset` 不要求训练数据存在；数据预处理脚本硬编码了作者路径，我用符号链接把官方路径映射到自己的数据根目录，官方代码保持零修改。

## 兼容性代价

官方 requirements 不锁版本，代价全落在 numpy 上：先是 numpy 2.0.2 与 torch 2.0.1 不兼容，之后发现官方 `embedding.py` 用了 `np.int`，而 1.24 已移除。我**不改官方代码**，把 numpy 定在 1.23.5，opencv 锁到同期的 4.8.1，Cython 限 `<3`（deep-person-reid 是 2020 年的代码），faiss-gpu 1.7.2 出乎意料地顺利。这些改动全部记进偏差表。

## 权重与数据的获取路线

DiffMOT 这边很顺：官方权重走 GitHub Releases，motion 模型（176MB）与 ReID 权重（157MB）已下载并算出 SHA256；YOLOX-X 的 DanceTrack detections 解压后结构正确，val 共 25 个序列、25508 帧。ReID embeddings 和 PlugTrack 权重都在 Google Drive 上，服务器直连不通（代理只加速 GitHub 与 HuggingFace），本地反而能访问，于是改走“本地下载 + 上传”，来源仍是官方链接，可审计。

## 一个和自家方法对上的细节

读完三个官方组件，语义确认：`bbox_final = α·bbox_kf + (1−α)·bbox_mp`，α 是 KF 的权重，搜索区间 [0.3, 0.7] 步长 0.1。这和我 reliability-ratio correction 里 s=0.4 的退化一致性设计正好对得上——本质是官方自适应混合的一个特例。这一点后面写方法时要展开说清楚。
