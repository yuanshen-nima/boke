一整天几乎没碰业务代码，都在给博客装一条“自动日报”管线：把我每天和 AI 编程助手的对话自动提取、脱敏、归纳成文章，再推上线。到晚上收工的时候，第一篇由 AI 归纳的《AI 对话日报 · 2026-09-06》已经进了仓库，等 Cloudflare 构建完就能看到。这篇就复盘一下今天做的事和踩过的坑。

## 先把两个数据源的消息结构摸清

ZCode 和 Codex 的会话存储方式完全不同：一个是本地 SQLite 数据库，一个是按日期落盘的 JSONL 文件。要写提取脚本，得先把字段对齐。

中间撞到一条特殊的子任务会话，内容全是系统注入，压根没有真实用户输入——如果不过滤，这类东西会被当成“我今天说过的话”喂给模型。把正常对话和它对比之后规律就出来了：系统注入块统一以尖括号开头的标签形式出现（比如插件推荐那类），真实用户输入就是普通文本。按这个规则过滤，干净利落。

字段确认完，脚本一鼓作气写完，两个数据源都跑通了。

## 提取 → 脱敏 → 归纳 → 发布

管线的四步定下来：读取当天全部会话全文、正则剔掉 key/token/密码样式的字符串、交给大模型按话题聚合成第一人称中文日报、写进 posts 目录并自动提交推送。同一天重复执行会覆盖重写，不会重复发。

为保险起见，我留了一个不走模型的降级模式：不调用 LLM，只按结构生成一版纯拼装的日报。这个模式的价值在验证——它能让我在不花钱、不依赖网络的情况下把整条链路跑通。

实测降级模式时，文章生成正常，但构建博客时冒出一个 postcss 报错。把完整报错看完改掉之后，构建以 exit 0 通过，新文章也被正常收录进索引。到这里，“提取 → 降级归纳 → 写文章 → 构建兼容”端到端全部打通，我才去更新说明文档、提交代码、注册定时任务。

## 接上真模型，用昨天的对话实跑

最后一步是把模型接上。我把 DeepSeek 的 key 写进本机配置——明确不进 git——先做最小连通性测试确认模型名，最终锁定 `deepseek-v4-flash`，然后完整跑了一遍 9-06 的日报（归纳 + 发布）。

结果比预期好。提取到 2 个会话、约 2 万字符，正好是单次模型调用的理想体量：一个是博客系统本身的搭建过程，另一个是我的无人机跟踪科研项目。生成的日报话题聚类清晰、第一人称、结尾有今日要点清单，检查下来没有文件路径、没有密钥，符合脱敏要求。

推送前我又在本地构建了一次，确认这篇文章不会把 Cloudflare 的自动构建弄挂。通过之后才 push。顺带把缓存目录加进了 gitignore，收个尾。

## 定时任务和它的一点不完美

计划任务已经注册好，每天 23:30 触发，名字叫 BlogDailyDigest，今晚是第一次全自动运行。

唯一的不完美是：它依赖电脑开机且 Windows 处于登录状态，错过不补跑。真要补救只能手动指定日期重跑一次。对个人博客来说这个代价可以接受，但值得记一笔。

- 完整管线“提取 → 脱敏 → 归纳 → 发布”端到端跑通，降级模式可离线验证整条链路，构建 exit 0。
